光标实验室：红点 ＋ 猫头

这一页是本站光标系统的定稿记录：为什么用红点＋这只猫，以及一套可以当场试玩的参数。试玩区左右对半＝深色主背景／浅色区对比，跨过中线光标会实时换脸；下面写清了每条取舍的理由。

① 看定稿与理由 ② 试玩 · 跨线换脸 · 看 FPS ③ 复制这套参数

A 为什么是这一套

不摆候选、只记定稿理由——光标为什么是红点、猫为什么是这一只、停多久扑、给多少表情。

光标＝红点，不画箭头

  • 热点在圆心，点击不会"差一点点"；图形光标的尖端容易对不准。
  • 红点是发光体、只在深色底上成立；所以光标一进浅色区就自动换羽毛逗猫棒（反射体）——这不是 bug，是规则。

猫头＝C5，矢量重绘自手稿

  • 按手绘原稿的三条语法重画：一笔连续轮廓、断轮廓当胡须、略扁椭圆。
  • 矢量用 currentColor 上色，跟着站点主色反色，深浅底都不会看不见；位图做不到。

停手 0.35 秒扑上去

  • 正好是"手停了、还没开始读内容"的空档，扑一下不打断阅读。

四态表情＋悬停放大

  • 眯眼笑／嘴努子（扑到）／耷拉眼（等久了）／眨眼，悬停放大 1.32×——有生命感但克制。

C 实时试玩区

鼠标移进下面这块，原生光标会消失、换成你选的组合（和网站上一样）。 左半深色＝你网站现在的背景，右半浅色＝测试对比度。里面有假的按钮 / 链接 / 卡片，用来触发悬停表情。

E 优缺点 · 重点难点

这样做的好处

  • 叙事闭环了。红点在前面跑、猫在后面追、手一停猫就扑上去——三个动作有明确因果，光标本身就在演示「逗」这件事，正好呼应你「会设计才能看懂设计」这个能力板块。
  • 笔触是你的，反色是白送的。C5 按你原稿的三条语法重画（一笔连续轮廓、断轮廓当胡须、略扁椭圆），用 currentColor 上色：站点主色改了它跟着改，进浅色区自动换深墨，深色底上不可能再看不见。位图版 C7/C8 只能预先导出两套资产才能做到同样的事。
  • 几乎不增加加载成本。W8 红点和 C5 猫头都是内联 SVG，合计约 3KB、零图片零请求；只有对照用的 C7/C8 位图需要预加载（约 74KB / 56KB）。
  • 叙事多了一层。扑点不再是「猫脸中心压住红点」，而是把嘴送到红点上（按每只猫的 mouth 坐标反算偏移），所以「叼住」是真的成立；停手满 4s 再换耷拉眼，变成「扑 → 叼 → 等累了」三层。
  • 可降级。关掉动效就是一个静态红点 + 一张静态猫脸，最坏情况也不比现在的圆点差。

代价与风险

  • 重画毕竟不是原样描。C5 保留了你的断笔、胡须接法、脸形和五官比例，但铅笔的毛边和压感只做到「像」，不是「就是」。要 100% 原样只能上位图（C7/C8），代价是换不了色、放大会糊。两条路都在页面上，随时可切。
  • 红点是全站唯一的高饱和色。暖金 + 米白的站色里突然出现一个 #FF2D2D，可能是点睛，也可能是刺眼——试玩区可以对比 W6 亮红 / 深红外红 / 暖金三种，你看了再定。
  • 比几何图形更抢注意力。招聘方一天看几十份作品集，一个会扑的猫头可能让人分心，也可能让人觉得幼稚。所以扑点默认 0.35s 才触发、只在你真停手时发生，不做无意义的持续动画。
  • 丢掉反色后，浅色区会变瞎。现在的 mix-blend-mode: difference 保证任何背景都可见；红点在米白底上对比度不够、猫头位图又不能加深，必须做「浅色区自动换深色资产 / 加描边」，比矢量版多一层处理。
  • 位图放大会糊。源图按 256px 导出，132px 预览已经接近上限，再大就有锯齿；44px 实际使用尺寸下没问题。
  • 发光是有性能成本的。drop-shadow 每帧移动会触发重绘。红点和位图默认都不套双层描边发光（对它俩没意义），要发光只用 filter，并带 FPS 实测。
  • 触屏 / 无障碍。触屏必须整个隐藏（现在已经做了）；另外要尊重系统的「减少动态效果」设置——开启时直接关掉扑点、只留静态跟随，以及 cursor:none 失效时要有原生光标兜底。

实施时的重点难点（按风险排序）

  • ① 热点对齐。SVG 的 viewBox 原点在左上角，热点却在羽尖 (4.2, 4.2)，所以定位不能再用 translate(x - size/2)，要改成 translate(x - hotX × 缩放比)，并且旋转也必须以热点为轴心（否则一转就偏）。这是最容易出 bug 的地方，我会做像素级校准。
  • ② 发光性能。方案 A filter: drop-shadow() 好看但每帧重绘；方案 B 双层描边（同一路径画三遍：宽而淡 → 中 → 细而实）零滤镜、几乎无成本，光晕略硬。选型页两个都能试并显示 FPS，我按你机器上的实测数字来定。
  • ③ 猫看棒的每帧计算。要算两个 lerp 后的位置差 → 角度 → 瞳孔偏移 + 头部倾斜。必须限制：瞳孔偏移 ≤2.4 单位、头转 ≤8°、且只在变化超过阈值时写 DOM，否则每帧改一堆属性反而更卡。
  • ④ 浅色区对比度。需要判断光标当前在深色还是浅色背景上。可靠做法不是算坐标，而是给浅色区块加一个 data-cursor-theme="light"，用 mouseover 冒泡读取——这样以后你新增浅色板块只要加一个属性。
  • ⑤ 表情状态机。现在是四态（眯眼笑／眨眼／嘴努子／耷拉眼）＋抖耳朵，同一时刻只能有一张脸。所以不用 class 叠加，而是每帧按优先级算出唯一的 faceNow 再挂 class；眨眼 170ms 后要让位，手动预览按钮还要能同步生效（不等下一帧）。
  • ⑥ 降级兜底。触屏隐藏、prefers-reduced-motion 关动效只留静态图形、JS 挂掉时保留原生光标（现在站点是 CSS 里写死 cursor:none，一旦 JS 报错光标就彻底消失，这次要改成由 JS 加 class 才隐藏）。
  • ⑦ 和模态框的冲突。Projects.jsx 的拖拽模态里有内联 cursor: grab / grabbing，会和 cursor:none 打架，需要一并处理。
  • ⑧ 原稿位图的资产管线（新）。你给的六张脸位置、留白、线条粗细都不一样，直接贴会出现「一换表情整张脸就跳一下」。所以每张都要走同一套处理：按 alpha 裁到最小外接框 → 补成正方形（×1.06 留边）→ 统一缩到 256px → 三态用同一个中心点对齐。这条管线已经写好并跑通，产物在 cursor-lab/assets/，以后你换脸只要重跑一次。
  • ⑨ 扑到之后要「叼住」。猫头不能再用几何中心对齐红点，得把 mouth 坐标（C5 是 20.8,28.4）反算成位移偏移，红点才会正好落在嘴上；这条偏移只在扑到的瞬间生效，手一动就退回右下。
  • ⑩ 一笔轮廓的代价。你要的「耳朵和脸之间不要有线」意味着耳朵不再是独立元素，所以「抖耳朵」只能改成整张头微抖（约 3°）。几何版 C1–C4 仍然只抖耳朵，可以对比一下你更喜欢哪种。
  • ⑨ 扑点的手感调参（新）。扑的触发阈值（0.35s）、扑过去的 lerp（0.3）、判定「扑到了」的距离（3px）、松口后退回的 lerp（0.08）四个数要一起调：太快像抽搐，太慢像卡了。这几个数我都提到配置里，你试玩区停手感受一下，报一个「感觉对」的档位即可。
